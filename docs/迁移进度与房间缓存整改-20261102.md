# 迁移进度与房间缓存整改

后续更新：[本地缓存自动迁云与并发上传](本地缓存自动迁云与并发上传-20261102.md)。下文记录早先版本；新版本将已有文件迁移与新文件下载策略分开，按云端去向迁移已有副本，并以批量核对和并发上传替代原有串行流程。

## 线上问题与原因

主源站原有 759 项云端任务已完成，当前没有排队、上传或失败任务。剩余本地文件主要属于已改为仅重定向的类别，不会因为配置了云空间而自动上传。旧页面没有解释这些跳过原因；扫描计数仅保存在进程内存中，重启后会从头显示。

## 后台改动

- 自动整理保存扫描游标、本轮和累计计数，刷新和服务重启后继续。每批最多核对 100 条普通资源和 50 条房间对象，核对与上传同时进行；本轮结束后进入定期检查。
- 展示未入队原因：仅重定向、保留本地、目标云端已有副本、已有任务、房间文件过期。无待上传任务时明确展示已核验数量，不把持续检查描述成一直上传。
- “缓存文件”页面提供“清理不再同步的本地资源”：先预览，默认不勾选，由用户选中文件后清理。只处理全部引用均为仅重定向或关闭缓存的对象；执行时重新检查策略、下载与迁移占用。共享缓存仍需要的副本跳过，云端实体不删除。
- 房间临时文件在有效期结束后立即从列表隐藏，定期清理同时删除文件登记和相关云端任务，不保留过期文件历史。其他房间仍有有效引用的实体继续保留。公共来源质量统计独立于临时文件历史。

## 房间加速

- 正常下载不等待源站清单查询；清单请求在后台执行，失败后继续原下载流程。失败文件补齐时仍可重新查询源站。
- 文件清单批量提交，源站比较公共来源、普通缓存和房间缓存，只要求补传缺失实体。
- 房主本地按文件路径、大小、修改时间等指纹复用 SHA-256/SHA-1，未变化的文件不反复完整读取。首次或变更文件仍需计算哈希，上传后由源站验证。
- 上传时读取源站确认数量、确认字节数及接收中状态。发送完毕不等于缓存成功；完成计数以源站上传确认或查询结果为准。
- 已知命中的源站副本优先使用；过期或下载失败继续尝试公共来源与房主文件。
- 批量计划不会清空房间清单中的公共下载地址，避免缓存过期后丢失原有下载兜底。
- 新面板默认展示三个数字、进度条、比例和速度；详细信息折叠。加速不是启动或正常下载的前置条件。关闭房间会取消后续上传并释放该房间引用，其他房间不受影响。
