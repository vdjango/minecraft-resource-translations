# 房间文件公开来源自动映射

目标：房主一次提交清单，房间不等待搜索；能使用快速公共下载就不长期保存文件实体，只在没有可靠地址时提供临时缓存。

## 决策与首次上传

1. 房主批量提交路径、大小、SHA-256、SHA-1、已知下载地址，可附已缓存的 CurseForge 指纹。
2. 源站通过本地索引批量对比公开映射与已有副本。快速公开映射优先返回重定向；已有副本直接复用。请求内不访问 CurseForge、不测速、不下载上游实体。
3. 未知或持续缓慢的文件立即返回待补传清单。首个文件上传、哈希核验完成后即可供成员下载，不等待整包或云端复制。
4. 后台持久化队列每批处理 12 个文件，查询最多并发 3 路；实体指纹计算最多 2 路。已有指纹合为一次 CurseForge 请求，不逐文件调用指纹 API。
5. 无指纹时先按文件名查找候选；已有核验实体时计算 MurmurHash2，并直接读取 ZIP 中的 fabric.mod.json、quilt.mod.json、mods.toml、neoforge.mods.toml、mcmod.info。仅读取每项最多 256 KiB，不解压到磁盘，不运行 JAR。
6. 指纹与名称只用于寻找候选。必须有 CurseForge 返回的 SHA-1 与实际大小完全一致，且存在受支持的公开 HTTPS 地址，才能建立映射。不同平台即使同名同版本，字节不同也不能互换；不能假定 Modrinth 的所有资源都在 CurseForge 存在。

## 存储与流量

| 状态 | 玩家下载 | 实体处理 |
| --- | --- | --- |
| 已有快速公开映射 | 直接返回 CurseForge 地址 | 不请求房主上传，不新增云端实体 |
| 首次未知、后台查询中 | 已接收文件可立即提供下载，原有直下/P2P 保持可用 | 先暂存；云端复制最多等待 60 秒 |
| 查到相同文件且快速可达 | 后续请求重定向 CurseForge | 取消未开始的云端任务，60 秒安全窗口后释放空闲本地临时实体；已上传云端的副本保留到房间租期结束，以免中断已下发的签名下载 |
| 地址已登记但采样额度不足或尚未确认快速 | 优先公开地址 | 保留已收到的临时副本，不主动重复复制到云端；真实下载失败后重新启用兜底 |
| 未查到、私有文件、连续慢或不可达 | 使用临时副本 | 按房间类别去向复制到本地/云端，仍受独立容量与默认 8 小时、最多 32 小时期限限制 |
| 成员报告公开下载失败 | 立即使用尚存的核验副本，否则请求房主补齐 | 本次故障不能被旧映射反复覆盖；必要时恢复云端复制 |

不为了查询映射先下载一整个 Modrinth 文件。房主已有文件只在源站请求补传时上传；普通资源下载策略仍独立生效。

CurseForge 可达性采样最多每次 128 KiB，沿用房间后台采样每日额度，默认 32 MiB，并发预留额度。下载速度从首批数据到达后计算，排除 DNS、TLS 与首字节等待；采样只观察约两秒的数据窗口，不等待整个文件下载。连续 3 次慢且滑动均速低于可配置阈值（默认 100 KiB/s）才判定持续慢。单次连接建立较慢不直接淘汰整个源。

两个公开 CDN 地址有时可达性不同。只在 CurseForge 公开的同一文件路径上切换受支持的 CDN，核对响应大小；记录实际可达的地址，已识别项目的新版本沿用该项目最近可用的 CDN。接口错误和 CDN 404 分别显示，不把“查不到”和“连接超时”混为一谈。

## 长期维护与关房

- 映射与临时文件分开存储；关房或实体过期不删除已建立的公开地址映射。
- 最近活跃的已识别项目每 20–28 小时随机错峰读取最近 50 个版本文件的元数据，登记 SHA-1、大小与公开地址；不抓全站，不预下载实体。
- 未命中结果负缓存约一天；接口错误独立退避重试，不阻塞其他文件。最多 25 秒的单文件查找期限，后台查询失败不阻塞正常下载。
- 关房释放该房间租期；没有活跃房间引用的任务不再执行，临时对象按现有清理逻辑移除。别的房间仍使用同一哈希时继续保留。
- 正在上传、正在供玩家读取、正在云端复制的文件不会被映射清理删除。
- 普通模组请求通过已核验文件建立的原始 Modrinth URL → 相同哈希 CurseForge URL 关系复用映射；房间文件、整合包修复也可以按 SHA-1 批量查询映射。

## 管理入口与兼容

`镜像 → 设置 → 房间临时下载加速` 增加“后台自动匹配 CurseForge”开关，显示排队、查询、待首传、已匹配及失败原因、最近检查和下次重试时间。配置只新增该开关；期限、容量、采样额度沿用现有集中配置。

源站返回 `public_lookup: background` 后，新启动器跳过原来上传前最多 2 秒的客户端 CurseForge 查询，直接补传需要的文件。旧启动器协议继续兼容，但旧 EXE 仍可能保留这段等待；源码修改必须随启动器后续版本发布才会生效。

官方 API 数据结构依据：[CurseForge REST API](https://docs.curseforge.com/rest-api/)。指纹碰撞可能存在，故必须额外核对 SHA-1 与文件大小。

## 本次核验

- 源站本地针对批量查询、首次补传、错误重试、关闭房间、下载失败回退、云端副本保护、归档标识和采样取消等行为的检查通过；Vue 类型检查与生产构建通过。
- 在主服务器用独立临时目录验证一个 399,105 字节的公开文件：首次清单约 11 毫秒返回补传需求，实体上传后服务端指纹与 CurseForge 一致；下一次计划返回公开映射，下载接口返回 HTTP 307。测试没有写入生产房间，也没有批量下载资源。
- 主源站已有房间任务已自动运行。未命中、采样暂慢或连接超时的文件保留兜底路径，不把所有文件都当成已成功映射。新 EXE 尚未在本次发布。
- 主服务器当前发布目录：`room-public-map-final-20261102-2e1d6cc06b`。在线核对时已匹配 27 个，2 个连接超时独立重试，11 个等待指纹信息。`mirror.bugg.icu` 使用启动器请求头返回相同公开映射的 HTTP 307；线上 Vue 文件与构建产物一致，镜像和译文服务均运行。
