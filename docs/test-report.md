## 查询性能

以下是在开发机 Windows / Python 3.11 / SQLite WAL 的本机 HTTP 合成压测。使用临时数据库，生产限流仅在该压测进程内停用，没有外部网络或模型调用；不代表互联网延迟、持续写入负载或首次生成性能。

### 批量译文查询

每请求包含 20 个字段。

| 场景 | 请求 / 并发 | 请求每秒 | 字段每秒 | p50 | p95 | p99 | 错误 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| LRU 热缓存 | 1000 / 20 | 1621.5 | 32430 | 11.53ms | 14.70ms | 20.53ms | 0 |
| 冷路径，绕开 LRU | 200 / 5 | 172.0 | 3441 | 28.63ms | 32.41ms | 33.68ms | 0 |

### 大译文库分页

10 万项物化列表记录，每页 20 项，各测 100 次顺序 HTTP 请求。只测试无筛选列表的 SQL、JSON 和 HTTP，数据为短简介，不包含正文、真实 metadata、FTS 搜索或持续写入。

| 位置 | p50 | p95 | 错误 |
| --- | --- | --- | --- |
| 第一页 | 5.87ms | 6.75ms | 0 |
| 第 99901 项开始 | 5.82ms | 6.42ms | 0 |

深页使用签名游标定位，SQL 没有深层 OFFSET。total_count 仍需计数，短词 LIKE 和大范围搜索可能更慢；这些结果不表示所有搜索都达到此延迟。

```text
python scripts/benchmark.py --requests 1000 --concurrency 20
python scripts/benchmark.py --requests 200 --concurrency 5 --cold
python scripts/benchmark_catalogue.py --projects 100000 --requests 100
```

## 部署边界

单服务进程 + SQLite WAL；系统服务使用持久数据库，原文核验和模型翻译在后台队列处理。当前不提供分布式多进程队列，不宣称无条件支持百万级写入。原文历史与 artifact 暂不自动清理，需要监控磁盘；扩容前迁移任务租约与数据存储。

启动器属于相邻 Buggcraft 项目；翻译与导航相关 12 项测试通过，覆盖设置开关、自动翻译、恢复原文、过期响应隔离、原文变更、HTML 格式与更新提示。本次不将其既有完整测试集的环境/旧模块问题计为通过。平台 Web 和 API 可以独立使用，无需启动器。
