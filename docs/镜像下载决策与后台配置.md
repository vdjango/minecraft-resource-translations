# 镜像下载决策与后台配置

## 目标

每类资源的来源、交付、存储、副本与失败处理形成一条完整链路。运营者能看见实际执行过程，不能把资源清单大小、远端来源覆盖量、本机暂存和云端副本混为一个“缓存量”。

## 后台入口

头部导航按工作领域分组，左侧导航是当前领域的子集。镜像资源负责观察，系统设置负责配置。登录页不展示管理内容；路由切换只刷新内容区域。

| 设置页 | 路由 | 唯一职责 |
| --- | --- | --- |
| 下载与来源 | /admin/mirror/settings/downloads | 来源仓库、六类资源的下载策略与存储去向、质量采样 |
| 存储与容量 | /admin/mirror/settings/cloud | 多个雨云、七牛或 S3 空间，独立容量/月流量/上传预算；集中设置房间文件去向、本地保留与上传中转容量 |
| 同步与分流 | /admin/mirror/settings/storage | 自动同步周期、预下载平台、并发、本机出口与协作节点 |
| 房间文件 | /admin/mirror/settings/room-cache | 节点授权、临时文件期限、来源决策与补传保护 |
| 域名与 CDN | /admin/mirror/settings/cloudflare | 域名、缓存绕过和公开文件缓存指引 |

旧来源、质量、分流设置路由转入对应的新入口。空间容量只在“存储与容量”设置；下载与来源只选择已有空间，不复制另一套容量输入框。

观察入口保留镜像概览、缓存文件、同步任务、房间临时文件、来源覆盖、来源质量。云端复制与迁移独立位于 `/admin/mirror/transfers`，同步任务只展示清单、核验与回源。概览首先展示使用中的云存储；本机数据明确标为暂存或历史副本。

## 请求决策

1. 校验文件路径并确定类别，固定下载路径映射到明确的发布地址。Mojang 游戏文件、Mojang Java、Maven、Forge/NeoForge/Fabric/Quilt、CurseForge、Modrinth 使用各自地址；不用含混的“官方”称呼。
2. 按文件查询已核验来源索引。一个文件可匹配多个来源，按长期质量与区域排序，跳过已知故障来源。普通请求优先重定向至可用来源，流量不经过本机或 OSS。
3. 启用质量缓存且所有候选持续过慢时，后台优先准备副本。尚无副本时当前请求仍使用可用来源，不等待现场测速或备份；后续请求可以使用已准备好的副本。
4. 没有可用匹配时，使用类别策略。纯重定向不产生实体缓存；缓存模式使用所选存储；备份模式平时直连来源，同时按需保存故障接管副本。
5. 所选存储为仅云端时，先使用已核验云端链接。本机出口预算和节点权重不限制云端链接，也不参与正常分流。云端尚未就绪、到流量保护线或不可用时，转备用来源或该文件原始发布地址。
6. 所选存储为本机或双副本时，本机出口预算和协作节点权重生效；接近本机流量、带宽或发送并发限额时转移下载。

例外：协作节点内部直达路径限制联邦跳转，防止循环；启动器显式要求本机实体的旧请求仅对本机缓存路线保留该语义，不能把仅云端路线强制改成本机响应。整合包归档通常只重定向；房间临时文件必须经节点授权。

## 各类存储与预算

| 项目 | 本机实体 / 双副本 | 仅云端 |
| --- | --- | --- |
| 来源映射优先查询 | 生效 | 生效 |
| 本机缓存容量 | 限制本机副本及下载预留 | 限制本机临时下载及待上传文件，不限制云端总容量 |
| 磁盘最小剩余 | 生效 | 生效，避免暂存写满系统盘 |
| 本机月出口、带宽、发送并发 | 本机实体响应生效 | 云端重定向不消耗该预算 |
| 协作节点权重 | 正常分流或故障兜底 | 不参与正常云端交付 |
| 云空间容量、上传量、月流量 | 对云端副本生效 | 生效，每个空间独立 |
| 上传完成后本机文件 | 双副本保留 | 上传校验和云端下载验证通过后释放 |

仅添加 OSS 空间不会改变资源去向。保存类别的云端去向后，后台自动检查已有实体、去重并分批加入上传队列，无需人工选择上传；新回源文件自动接续上传。每批检查至多 100 条普通引用和 50 个房间实体，待处理队列达到 200 项后暂停领取下一批。只处理本来已有的实体，纯重定向策略和只有元数据的清单不会因此下载整库。新选择云空间默认仅云端，额外本机副本需要主动选择。

房间文件容量集中在「存储与容量」，三个边界独立：本地保留容量仅限制本地/双副本，允许设为 0；云端中转暂存容量仅限制等待上传的房间实体，仍受磁盘最小剩余保护；云空间容量和月流量按每个空间独立计算。本地设为 0 不关闭云端补传，直接保存到云端仍需有限中转暂存。仅云端文件在上传与下载核验后释放暂存，不再因月流量配置暗中保留副本；流量用尽且无其他可用来源时明确不可用，不能承诺无来源也可下载。云端流量按签发文件链接预留，可能与服务商账单存在差异，以账单为准。

## 同步到底在做什么

| 阶段 | 行为 | 文件在哪里 |
| --- | --- | --- |
| 扫描清单 | 读取版本、资源索引、Java 平台元数据，登记哈希、大小、平台 | 本机只有元数据 |
| 核验来源 | 分批核对仓库校验值，建立文件到多个来源的映射 | 不下载完整资源实体 |
| 策略筛选 | 排除非所选平台、纯重定向和已有健康来源覆盖的项目 | 不新增实体 |
| 回源下载 | 从明确的来源下载并核验，失败切换已核验替代来源 | 本机暂存；显示文件、平台、来源、最终去处 |
| 上传云端 | 对指派云空间的文件上传、校验哈希和大小 | 单独显示上传队列、数量、状态和具体错误 |
| 验证并释放 | 验证云端下载后释放可安全删除的仅云端本机副本 | 最终云端；双副本、共享本地引用或未完成的其他目标副本继续保留 |

任务显示本批各类别文件数与预期去向、来源覆盖跳过、纯重定向跳过、云端暂停跳过、平台跳过、复用已有副本、新完成与失败数。跳过不是失败；容量上限不是填满目标。

流程卡高亮当前扫描、来源核验、筛选回源或云端上传阶段；同时展示当前仓库、本批校验进度与正在核验的文件。回源列表显示实际使用的来源、平台、字节数、速度与开始时间，本机暂存目录和最终对象目录直接可见。云端任务显示原始文件名、空间名称、完整对象路径、上传进度、下载检查结果，以及本机副本是否因共享引用或兜底保护保留。回源下载与云端上传是两个独立队列：下载并发不等于上传并发，当前云端逐个上传。

当天上传预算耗尽时不假报失败，保留暂存并显示下一次自动继续的时间。仅云端类别的请求不会等待完整回源与上传；准备副本在后台进行，当前用户先直连可用来源。新配置与已生效配置分开展示，观察页按已保存的设置和实际传输信息显示。

### 云端复制与迁移观察台

- 上传启停集中在存储与容量和云端复制与迁移页顶部，两个页面使用同一 Vue 组件及 Pinia 状态。点击立即保存单独的上传开关，不提交其他未保存的表单；暂停时完成当前文件后停止领取新任务，下载不受影响。
- 顶部显示待上传数量与大小、已完成数量与大小、需要处理的任务及实时上传速度。活动文件显示类别、目标空间、原始文件、对象路径、已传字节和耗时。速度由真实上传回调近 8 秒的字节增量计算；校验阶段显示校验中，停止传输时不虚报上传速度。
- 分类摘要覆盖整个任务索引；列表按类别、状态筛选和分页查询，每页 20 条，不再只能看到最后 20 个文件。刷新保留当前筛选及页码，已有行保留并显示刷新状态；首次读取显示列表骨架屏。
- 分批迁移扫描全部本地资源引用，按哈希去重并排除已有队列或云端副本，不再漏掉最近 1,000 个文件之外的类别。房间临时文件只选择仍在租约期内的副本。每批最多新增 200 项，不自动扩充容量和上传预算。
- 排队、上传暂停、每日预算等待、缺少配置、容量不足、文件丢失、上传或校验失败分别展示。失败项不阻塞后续任务，修正对应问题后可单独重试。
- 保存、启停和任务提交在右上角显示非阻塞浮动通知，失败保留可读错误；初次加载与后台轮询不弹成功通知。操作设超时和重复提交保护，避免按钮无期限等待。

### 下载入口核验与超时

「已上传并核验」指对象已写入且大小、哈希匹配，下载入口状态另行显示，不能把域名故障标成全部完成。S3 自定义域名 HTTPS 不可用时，以同一空间的原始 S3 地址重新签名并做最小 Range 下载验证；仅验证通过才切换并释放暂存。签名保持正确的 Host、方法与租约期限，不直接替换签名 URL 的域名。两个入口均失败则保留已有暂存、显示具体原因并继续其他任务。

状态读取与长操作使用独立连接池和超时。切换路由取消旧页面请求时静默清理，不弹连接超时；真实超时保留列表，轮询失败逐步退避。耗时联通测试允许较长截止时间，避免页面默认期限提前截断操作。外部网络故障仍需以实际状态和日志判断，页面不把所有取消都归为网络超时。

预下载平台在保存时统一转换为有序且去重的列表，兼容旧版单选和全部平台设置。云空间启停、容量等局部保存保留原平台选择；无效输入给出可操作的中文提示。

单个失败进入持久补齐队列，其他文件继续；可批量重试失败项，不重做成功文件。空间保护触发时明确说明暂存满或磁盘保留线，尚未处理文件留待下一轮。上一轮仍在运行时，定时同步顺延，不叠加任务。

## Windows 与 Linux 文件

.so 是 Linux 动态库，Windows 通常使用 .dll。清单为了支持多个系统保留全部平台，不代表都要提前下载。在「镜像设置 → 同步调度 → 预下载平台」多选 Windows、macOS、Linux，可任意组合；默认仅 Windows，升级不自动扩大下载范围。全部取消表示只扫描、不预下载实体，玩家按需下载仍支持所有平台。通用文件只进入同一轮队列一次，实体按哈希去重。平台选择与分类下载策略、来源命中、存储去向和容量上限同时生效；54.01 GiB 是全部平台清单的潜在总量，不是所选平台的下载量。新增平台的历史文件在保存后点击「同步任务 → 继续预下载」补齐，修改平台不自动删除已有缓存。Java 清单和原生库记录平台，旧清单按 .so、.dylib、原生库文件名兼容过滤。升级后增量扫描补全 Java 平台标记。

既有 Linux 文件不在保存配置时删除；本地空间清理与云端历史文件处理仍独立保护数据。

## 大量来源映射

映射索引支持最多 100,000 个文件路径，覆盖五万文件场景；一个路径可含多个候选源。下载按索引查找，不在请求中全盘扫描或集中测速。来源核验每批最多 128 项、最多 4 路；大清单分页展示，不把五万行同时渲染到浏览器。来源 JSON 清单上限 16 MiB。质量采样继续错峰、小量、预算受限。

统计必须区分“已核验远端文件”“请求重定向命中”“本机实体副本”“云端已核验副本”。映射命中不代表玩家已完成远端下载。
