# 客户端文件加速与缓存有效期

适用入口：游戏安装、整合包导入与补齐、资源下载、房间同步。启动器提交一批文件哈希，源站一次返回已命中的来源或副本；未命中交还原下载流程，不等待源站完成回源。

## 三种时间分别控制什么

| 设置 | 作用 | 到期后的处理 |
| --- | --- | --- |
| 版本清单缓存的重新检查间隔 | 版本列表、加载器清单等可变信息 | 重新检查上游；不会因此清理资源实体 |
| 客户端临时副本保留时间 | 玩家获准补传的临时文件，默认 8 小时、最长 32 小时 | 清理临时实体和已过期的私有记录；已验证公开映射保留 |
| 云空间签名链接有效期 | 某个私有对象下载地址的授权 | 后续请求重新签名，不代表对象被删除 |

普通镜像副本受类别策略、存储空间容量和淘汰规则管理，不受临时文件的保留时间限制。

## 一次批量请求如何选路

1. 读取公开发布地址索引、仓库映射以及普通镜像和临时副本索引。
2. 优先使用已经确认快速的同文件来源；来源速度采用已有的后台质量观测。
3. 没有快速来源时复用已存在且可下载的副本。
4. 没有副本时尝试质量尚未判差的同文件公开来源；没有命中则保留原下载途径。

仓库映射覆盖后台启用的阿里云、华为云、公共 Maven、Minecraft 镜像与自定义来源。匹配必须有相同哈希、已知文件大小，失效或被禁用的映射不参与。先前只有模组发布地址进入这个批量查询，现在依赖库和普通镜像副本也参与。后台补查发布地址是另一项异步工作，当前使用 CurseForge 指纹和内容信息核验；它不控制仓库扫描开关。

数据库对来源 SHA-1、已知文件 SHA-1、缓存 SHA-1 建立索引；请求最多 3000 个去重哈希，SQL 每批 300 个，既不逐个发 HTTP 请求，也不在前台扫描全部仓库。旧的 `/room-cache/resolve` 路径保留以兼容现有启动器，其查询和可下载副本供所有下载入口复用。

## 存储、清理与授权

全站共享的是文件身份、来源质量和已验证副本，不代表接收任何客户端上传。只有已获节点授权、且源站明确要求的房主文件可以补传。普通下载和整合包导入可匿名批量查询，不能登记任意来源、获得上传权限或延长临时文件寿命。

临时副本继续按模组、资源包、光影配置本地或云空间；本地上限为 0 不会关闭云端容量。普通镜像副本继续使用自己的类别去向。下载使用云端时计入目标云空间预算；从服务器发送时遵守本机出口与并发限制。未命中、到期和迁移失败都不能在下载请求中重新下载整个文件后再回传。
