# 资源镜像、容量测量与部署

调研及实测日期：2026-10-30。目标域名 `mirror.bugg.icu`，现有译文库与 API 保持原入口。新页面 `/mirror`，管理 `/admin/mirror`。

## BMCLAPI 缓存范围与本实现

根据 [BMCLAPI 官方文档](https://bmclapidoc.bangbang93.com/)，服务涵盖 Mojang 版本清单、版本 JSON、资源索引、游戏客户端/服务端、资源对象、依赖、Java，以及 Forge、NeoForge、Fabric、Quilt、LiteLoader、OptiFine、authlib-injector 等。它不是普通模组/整合包的全站镜像。OpenBMCLAPI 是分发节点程序，不是可直接替代中心服务的开源站点。

文档不允许二次封装其服务，因此此实现直接访问官方来源。不存在向 BMCLAPI 批量抓取的代码。公共资源的权利仍归各上游；本仓库 AGPL 不会授予第三方资源的再分发许可。

| 内容 | 当前能力 | 容量统计 |
| --- | --- | --- |
| 官方版本清单、版本 JSON、资源索引 | 按需缓存；可扫描全部公开版本 | 已测量 |
| 原版客户端、服务端、映射表、Windows server | 哈希校验、去重、预下载 | 已测量 |
| 原版音效、语言、贴图等资源对象 | 哈希校验；不是第三方资源包 | 已测量 |
| 游戏依赖、全部平台 native、当前 Mojang Java raw/lzma | 缓存、预下载 | 已测量 |
| Forge、NeoForge Maven 文件 | 允许的加载器及依赖路径按需缓存 | 全历史未测量 |
| Fabric、Quilt 官方 metadata 与加载器 Maven | 按需缓存；限制命名空间，排除 Fabric API 等普通模组 | 全历史未测量 |
| authlib-injector | 固定官方域名路径回源，不跟随重定向 | 全历史未测量 |
| OptiFine、LiteLoader、旧 Oracle Java | 暂不提供 | 未测量 |
| 普通模组 | 默认本地关闭、跳转官方；可开启按需缓存或重定向 | 不扫描模组站 |
| 整合包、第三方资源包、光影 | 不提供 | 排除 |

当前**不是 BMCLAPI 的全部 API 的直接替代品**，例如 Forge 查询 API 尚未实现。加载器 Maven 可用不等于已同步整个仓库。客户端需要映射 JSON 中的下载 URL；JSON 保留官方原文与 SHA-1，不能简单把清单域名替换后就假设所有嵌套 URL 已更改。

启动器应在发起每次下载前替换来源，保留文件路径与哈希；不要改写版本 JSON 的字节后继续使用官方 JSON 哈希校验。常用映射如下：

## G 盘实测

初次检查 G 盘：总计约 1.89 TB，已用 1.23 TB，剩余 **657,089,069,056 字节，约 612 GiB**，与“已使用 600G”有差异。此数值是磁盘当时的实际可用空间。

从官方 `version_manifest_v2.json` 扫描 **921 个公开版本**，读取全部列出的 downloads、libraries/classifiers、logging、assetIndex，再扫描当前 Java 全平台 manifest。以官方 SHA-1 去重；无 SHA-1 的元数据按 URL 计数。完整结果：**23,526 个唯一文件，57,993,169,280 字节 = 57.99 GB = 54.01 GiB**，未知大小 0，扫描错误 0。

| 类别 | 字节数 |
| --- | ---: |
| 客户端 | 15,585,002,558 |
| 服务端 | 29,125,705,767 |
| 客户端映射表 | 2,989,261,030 |
| 服务端映射表 | 2,192,768,161 |
| Windows server | 1,794,912,563 |
| 游戏依赖 + native | 1,008,661,688 |
| 原版资源对象 | 1,851,751,873 |
| 当前 Java raw + lzma | 3,397,094,023 |
| JSON 元数据 + 日志配置 | 48,011,617 |

这些是清单声明的资源净大小，不含 SQLite、索引、临时文件、文件系统分配开销及单独保存的扫描 JSON。Java 同时保留 raw 与 lzma，涵盖各平台；不是只计算当前 Windows。已有内容按 SHA-256 再去重存储。建议为这一范围预留 70–80 GiB。

**这不是 BMCLAPI 全站容量。** 官方公开接口没有提供本次可核验的全站字节清单。加载器的整个历史 Maven、已从当前 Java 清单移除的旧运行时，以及暂不支持的项目仍未计入，不能据此声称“完整复制 BMCLAPI 只要 58GB”。原版实测范围可以放进 G 盘；全部加载器历史是否可放下，需另行枚举与测量。

机器保存的可更新证据：`G:\BuggcraftMirror\inventory.json`（含每个 URL、路径、大小、SHA-1）；`inventory-report.json`（摘要）。数据随上游版本更新变化；在管理页可重新扫描。预下载完成与否以后台的任务状态、错误数和已缓存字节数为准。

## 进程与存储隔离

翻译应用仍监听 `127.0.0.1:18448`。镜像独立监听 `127.0.0.1:18449`，使用自己的 HTTP 连接池、SQLite 与文件目录；大文件不经过翻译应用。翻译后台仅通过两条独立管理连接访问镜像进程，3 秒超时，离线时翻译 API 继续工作。

默认缓存上限 400 GiB，磁盘保留 100 GiB，最多 4 个下载、单文件最多 2 GiB；未知 Content-Length 按 2 GiB 保守预留。后台可改为 50 GiB 等容量。配额同时计算完整对象与下载预留；SQLite、扫描清单、日志和文件系统分配开销另需少量空间。顺序预下载为前台留出并发位置。默认优先新版本并保护最新 2 个原版版本引用的文件；旧版本不能挤掉新版本，可改 LRU 或“满了停止新增”。正在发送的文件禁止淘汰；配额不足时下载不落盘，公开请求转其他节点或来源，后台预下载停止并显示空间保护。保护对象和进行中的预留超过所填容量时拒绝保存更低值。两进程共享物理磁盘和网络，独立进程不能保证网络拥塞时零影响；生产环境可配合系统 QoS/带宽限制。

六类可独立设为缓存、重定向、备份并重定向、关闭本地服务（回退官方）。核心及加载器默认缓存；Java、依赖与 assets 默认备份重定向；模组默认不缓存。备份只覆盖已保存且未淘汰的资源，重定向不会等待备份完成。已有副本异步探测上游，故障判定后后续请求读本地；已发出的重定向无法撤回，需要客户端重试镜像地址。可手动切为缓存立即使用现有副本。

默认 30 分钟后台增量检查，可设 5～1440 分钟或关闭。签名不变的版本和 Java 元数据跳过；新版本引用旧资源索引时从已验证 JSON 缓存读取以更新共享资源优先级。只预下载变更项，并更新 Fabric/Quilt/Forge/NeoForge 的可变加载器目录。失败刷新保留上次完整清单。容量计数预先维护，URL 使用主键索引，公开文件请求不遍历磁盘。

多站点按权重与健康分流，20 秒探测，90 秒健康租期；只选择类别为 cache、协议匹配且接受下载的节点。接近本机月出口/最近一分钟带宽准入预算、发送并发上限，或磁盘不足/回源失败时：健康资源节点 → 已配置且探测可用的备用源 → 官方地址。307/no-store 让客户端直接下载，直达节点路径不再跳其他联邦节点。预算按接受的文件/Range 长度预先记录，取消和条件请求可能保守多计；不等于运营商账单或链路限速。

公开来源映射自动生成，优先于分类策略，直接映射的文件不新增缓存、备份或预下载。内置阿里云、华为云、南京大学和 Maven Central，允许添加其他源；以每个文件的 SHA-1 核验，不把整个 `/maven/` 指向一个仓库。原 920 个 Central 精确映射作为扫描种子自动采用。后台按源统计核验覆盖、本地副本与下载跳转，分页列出文件。匹配成功后可选择移除本地副本；默认不自动删除，实际清理前重新检查远端可达、大小与校验值，并保留正在使用或仍有其他引用的对象。校验小文件并不等于下载了所有二进制，客户端仍应检查原始 SHA-1。Linux 的 Adoptium 软件包可作为独立 Java 安装来源，不能替换 Mojang 清单指定的不同文件。

完整需求与阶段见 [镜像服务实施清单](镜像服务实施清单.md)，其他人部署和加入资源网络见 [资源节点部署](资源节点部署.md)。当前接纳由管理员配置，不是自动批准未知节点。公网域名及其他资源节点尚未部署。

临时下载只在完整长度及已知 SHA-1 校验通过后原子发布；缓存物理对象按 SHA-256 去重，支持 HEAD、Range、If-None-Match。中断后重试会跳过已完成文件；未完成的大文件重新下载，不承诺上游字节续传。资源 URL 不能指定任意上游，不跟随重定向，固定 HTTPS 官方域名列表。公网入口必须屏蔽 `/_internal/`，控制令牌只在本机读取，不显示在页面。

扫描只下载 JSON，二进制预下载由后台按钮单独启动。关闭终端不影响独立隐藏进程；电脑关机后需重新启动进程并点“继续预下载”。不要同时启动两个使用相同缓存目录的镜像实例。

## Windows 本地启动

在仓库目录安装依赖：`python -m pip install -e .`。翻译应用和镜像使用相同的 `TRANSLATION_MIRROR_ROOT` / `TRANSLATION_MIRROR_PORT`，设置保存在镜像目录的 `settings.json`，无需共享翻译数据库。

```powershell
$env:TRANSLATION_MIRROR_ROOT='G:/BuggcraftMirror'
$env:TRANSLATION_MIRROR_PORT='18449'
python -m mc_translate.mirror
```

也可使用 `deploy/start-mirror.ps1 -Python <python.exe>` 隐藏启动，输出和 PID 保存在 G 盘镜像目录。镜像支持 `--env <文件>` 与 `--root <目录>`；加载现有翻译 `.env` 不会启动翻译 worker，也不调用模型。

翻译服务照常启动 `python -m mc_translate`；使用现有管理员登录统一后台 `/admin/settings`，在「存储与同步」页签先扫描，再预下载。在其他页签设置六类下载策略、公开来源、分流和域名缓存；旧 `/admin/mirror` 跳转到下载策略页签。Linux 示例在 `deploy/buggcraft-mirror.service`；按实际安装路径和服务账户调整，翻译进程也应设置相同镜像根目录。

## 域名、Nginx / Tunnel 与 Cloudflare

保留现有翻译域名。为 `mirror.bugg.icu` 新建公网入口，DNS 橙云代理，SSL/TLS 为 Full (strict)，源站用有效证书。若缓存留在本地电脑，可使用 Cloudflare Tunnel，配置示例 `deploy/cloudflared-mirror.yml`，填入已有 Tunnel 身份后先运行 `cloudflared tunnel ingress validate`。这些是配置模板，不表示 DNS 已修改或公网已部署。

Nginx 在新域名 server 内同时 include `deploy/nginx.conf` 和 `deploy/nginx-mirror.conf`，先执行 `nginx -t`，再 reload。现有翻译 server 不需要 include mirror 文件。特别注意：网页的 `/assets/*.js` 和 `/assets/*.css` 走翻译应用；只有 `/assets/两位SHA前缀/40位SHA` 走镜像。`/v1/packages`、`/v1/objects`、Java runtime 走镜像，其他 `/v1/*` 仍走翻译应用。SSE 保留原有关闭缓冲的配置。不要把整个 `/v1` 或 `/assets` 全部导向镜像。

后台 Cloudflare 指南会按所填域名生成两条表达式：资源路径设为 Eligible for cache，遵循源站 Cache-Control；管理、翻译 API、管理 Cookie、Authorization 请求的 Bypass 规则放最后。不要设置全站 Cache Everything，不强制缓存错误响应。哈希对象一年 immutable，可变 JSON/XML 五分钟；HTML、管理和状态接口 no-store。

根据 [Cloudflare 默认缓存规则与文件大小限制](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/)，JSON 和无扩展名资源需要明确设为可缓存；Free/Pro/Business 的单文件缓存上限为 512 MB，Enterprise 默认 5 GB。[Cache Rules 顺序](https://developers.cloudflare.com/cache/how-to/cache-rules/order/)中后匹配的冲突设置优先。缓存可能被逐出，不替代本地副本；大量软件下载分发需核对所选 Cloudflare 产品的适用条款与容量。

验收时重复请求同一文件，检查 `CF-Cache-Status: HIT` / `Age`、正确 Cache-Control、Range 206 和 Content-Range。冷缓存要先把上游文件完整下载、校验后才能发送；大文件可先预热，否则可能遇到代理等待超时，后台下载仍会继续。不得通过 Range 绕过 CDN 整文件大小上限。

真实清单再次增量检查：921 个版本、23,526 文件，版本变化 0，只更新 2 个可变 JSON，用时约 1.65 秒。缓存 HEAD 100 次本机循环请求中位 3.116 ms、P95 3.467 ms；状态接口中位 2.320 ms；独立内存 SQLite 的 URL 主键查询在 1000/100000 行时中位 2.1/2.7 µs，查询计划均为索引查找。该测量只验证本地请求与索引开销，不代表公网吞吐或大型并发压测。
