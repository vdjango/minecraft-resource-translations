# 本地缓存自动迁云与并发上传

## 原因与行为

2026 年 11 月 2 日检查主源站：云端已完成 797 项、约 1.70 GB；本地仍有 6,369 个实体、约 15.25 GB，主要是游戏核心和原版资源。它们已选择雨云空间，但下载策略为“仅重定向”。旧版自动整理把下载策略同时当作迁移开关，导致反复核对却不排队。这是迁移逻辑的问题，不需要通过开启新文件下载来解决。

修正后，下载策略决定是否从来源获取新文件；存储位置决定已有本机文件迁到哪里：

| 存储位置 | 已有本机文件 | 后续新文件 |
| --- | --- | --- |
| 本机磁盘 | 保留本机 | 按下载策略决定是否缓存 |
| 仅云端 | 自动上传、校验云端对象与下载入口，安全后释放本机副本 | 按下载策略决定是否获取；需要缓存时存入该空间 |
| 本机与云端都保留 | 自动复制，保留本机 | 按下载策略决定是否获取；需要缓存时保留两份 |

“仅重定向”不会启动新资源的预下载，已有文件仍可迁云。其他仍需本机副本的共享引用、正在使用的文件及未完成的其他迁移会阻止过早删除。房间临时文件还必须处于有效期内。

## 性能与进度

- 普通资源每批最多 500 条，房间对象每批最多 100 条；按索引批量比较云端位置、去重并批量入队，不逐文件网络测速或读文件做清单核对。
- 任务队列以 600 项为窗口，核对与上传同时执行；达到窗口后先处理队列，游标持久保存。
- 云端上传复用已有“本机与调度”并发数，范围 1–8；不增加一套重复配置。每个上传独立显示进度、速度、类别、目标空间，总速度汇总显示。
- 雨云/S3 上传前的 SHA-256 和 ETag 在一次磁盘读取中计算；逐对象仍核验云端大小、哈希元数据及 ETag。下载入口健康在短时间内复用，避免每个文件重复建立相同的 HTTPS 连接，后台继续定期复查入口。
- 并发任务在开始前原子预留容量和每日上传预算，成功后转为实际占用，失败释放预留。等待在途预留释放会自动重试，不误判成整天不能上传。
- 网络断开及 HTTP 408/429/5xx 最多自动尝试 3 次，期间继续处理其他文件；权限或内容校验失败独立保留具体原因。修正了没有 HTTP 响应时错误格式化本身抛出 `NoneType` 的问题。暂停阻止新上传，已开始的任务完成；恢复后自动续传队列。

保存存储去向后，后台下一次检查通常在 30 秒内发现变更；进程启动后首批核对等待约 5 秒。开始上传不需要打开观察页面。

## 入口与验证

后台“镜像 → 资源去向”选择各类文件的云空间及本机保留方式，保存后到“云端复制与迁移”观察任务。上传保护须处于“后台上传已启用”。

针对性验证覆盖：批量去重、刷新与重启断点、仅重定向类别迁移已有文件、并发任务独立进度、单任务失败后继续、容量与每日预算预留、S3 单次读取指纹、Vue 表单选择及并发卡片；前端类型检查与生产构建通过。未进行额外批量测试上传。

## 部署结果

主源站已部署 `cloud-batch-final-20261102-641355f239`，镜像与翻译服务均为运行状态，上传并发沿用线上配置 8。已有本机文件已自动开始迁移；观察时云端完成数从原来的 797 项增至 3,555 项，592 项待上传、8 项正在处理，失败项为 0。已恢复 7 项实际通过云端核验但被旧数据库提交冲突误标失败的任务，没有重复上传或重复计入上传预算。

公网 Vue 资源返回 HTTP 200。不同文件大小与实际出口带宽会影响实时速度，不能把并发数直接当作带宽倍数；页面总速度包含短任务完成前已发送的字节，避免只统计当前大文件。
