# 后台信息架构与资源观察台

## 目标与边界

2026-11-01 更新：镜像配置与下载决策的当前规范见 [镜像下载决策与后台配置](镜像下载决策与后台配置.md)。下表同步收拢后的入口；容量、来源和类别去向不再分散重复设置。

统一平台、账号和导航。管理后台分为「资源与任务」「设置配置」两个区域；镜像是主业务，翻译是平台中的一个功能。登录就是独立的登录页，未认证时隐藏工作区导航与数据面板。节点用户登录、节点管理员登录、下载站管理员登录采用相同原则，保留各自已有的认证与权限边界。

## 资源与任务的真实含义

- 普通镜像资源只列已完成校验的本机或云端缓存索引，不把发布者清单当作本机文件；文件数是 URL 引用数，磁盘占用按本机实体对象去重，云端副本按空间单列。
- 客户端先提交文件信息。直下/重定向记录不占实体空间；只有被源站请求补传并成功校验的对象计入临时占用。多房间引用同一哈希只保存一份，清理时间取仍有效需求的最晚到期时间，轮询不续期。
- 临时缓存等待补传、上传中、可下载、已到期、正常直下分别展示；原因与状态分开，服务器未收到上传时不伪称上传失败。后台不展示或泄露房间授权令牌。
- 同步任务展示当前阶段、开始/结束时间、计数和失败摘要。没有可靠总量的扫描显示已扫描量；不编造百分比。正在回源的文件显示已接收字节、总量（已知时）和平均速度。
- 最近同步任务保留最近 100 条，重启后可读；重启中断的任务标记为中断，不伪装成仍在运行。临时上传属于实时活动，与镜像同步任务分开展示。
- 概览展示「下次自动同步」与「最近同步」，同时链接到任务页。配置页仅展示配置、保存结果与相关观察页入口。

## 列表、刷新与性能

首次读取在对应表格/卡片区域显示骨架屏；刷新保留已有记录，列表内显示刷新状态。失败保留旧数据，提供就地重试；翻页与筛选同样遵循此规则。空列表、离线、加载失败分开表达。加载动画遵循减少动态效果偏好。

普通缓存与客户端文件在 SQLite 中分页查询，使用索引与游标，禁止逐次遍历磁盘；不把全量清单发到浏览器。每页最多 50 条，搜索限长、SQL 参数化。状态页在可见时每 5 秒刷新、闲置页暂停，不重复提交同步或测速任务；用户正在编辑的配置不被轮询覆盖。采样仍在后台随机错峰，用户下载不等待即时测速。

## 2026-11-01 后台收敛与故障处理

- 统一管理头部导航为「统计总览、镜像资源、译文与用户、节点网络、设置」，左侧按工作台、镜像源、翻译与平台、设置分组。进入 `/admin` 首先看到资源与访问统计；镜像观察与策略配置保留独立路由，避免把所有内容堆在一个页面。
- 本地缓存占用只读已完成、已校验的对象；资源清单总大小和“按策略可预下载量”属于潜在规模，绝不标成已缓存。容量上限是硬上限，不保证自动填满。显示当前占用、配额、磁盘保留量、最多还能新增多少，以及上一次预下载是否被停止或触及空间保护。
- 任务页分成当前任务、失败文件、实时上游下载、云端迁移、来源映射与空间预留、历史记录。失败展示来源 URL/路径、HTTP 状态或网络错误、可能原因和处理建议；提供「只重试失败文件」，成功文件不重下。历史里仍可展开过去任务的错误。来源扫描错误在对应区域直说，不用“请检查错误”一类空泛提示。
- 后台预下载按配置并发运行，至少留两路给玩家实时下载；每个文件失败后继续处理其他文件。定时刷新只处理增量，若上一任务未结束则顺延，不叠加第二个同步。主源暂时不可达时可尝试已接入且健康的协作节点；仍按原始文件的大小、SHA-1 或对象哈希校验，不接受未经验证的数据。
- 来源覆盖把已核验文件、本地副本数、本地字节数、重定向命中分列。来源质量展示近七天图表、百分制得分、64/128/256/512/1024/2048/4096 KiB/s 速度档位、可用率和样本；至少八次、跨三天才给正式分数。评分和缓存优先级只是辅助，类别下载策略与空间上限仍优先。
- 房间客户端临时容量在页面用 GiB 输入，提交时换算为后端 MiB；不会与普通镜像缓存额度混为一谈。列表刷新保留旧数据，首次加载才显示骨架；后台状态轮询不覆盖正在编辑的配置。

### 失败文件的补齐语义

- 单个文件下载连续失败时记入 SQLite 待补齐队列，记录 URL、类别、HTTP 状态、原因、失败次数和时间；同一批次其他文件继续。重启后队列仍在，成功缓存或已改用可靠重定向后自动移除。
- 「只重试失败文件」每次选最久未尝试的至多 200 个文件，不重下已成功文件；失败项更新尝试时间并移到队列后面，下一批不会长期被同一文件占住。磁盘配额耗尽仍会暂停预下载，避免突破空间保护。
- 下载时先尝试原始来源；连接失败、HTTP 404 或 502 时依次尝试最多两个已配置或自动核验的来源映射，再尝试健康且启用缓存的协作节点。返回内容仍以原始 URL 的 SHA-1/大小要求校验；替代来源全部失败时保留各自原因，等待后续批量重试。协作节点专用请求只在该节点取文件，禁止再跳向其他映射或节点，防止循环。
- 资源清单扫描失败与文件下载失败分开展示：前者通过「扫描资源清单」重试，后者通过待补齐队列重试。同步周期到点而已有任务在运行时顺延，不取消或叠加当前任务。

## 2026-11-03 导航与控件收紧

- 后台仅保留一层主导航：「总览、镜像资源、翻译服务、节点与接入、系统设置」。菜单由共享配置生成，左侧只展示当前主分类的子项；公共站点导航不出现在后台，未登录时不展示后台菜单。
- 页头、设置分类、表格行距统一收紧；输入框、下拉框与普通按钮统一为 36px，复选框为 16px。预下载平台采用紧凑多选项；窄屏表格在自身区域横向滚动，避免挤成竖排。
- 来源质量同时展示 Maven 仓库、Minecraft 镜像和内容 CDN。显示来源类型、有效映射覆盖数、近期状态、速度与长期评分；无覆盖和等待采样分别提示。
- BMCLAPI 的正常 302 节点分流继续跟随测速，整条链限制 10 秒、最多 5 个请求，仍遵守采样字节预算和公网地址校验。旧版把 3xx 误记为失败的样本清除后重新错峰采样，不改动真实下载失败记录。

### 卡片密度与统一节点入口

- 节点管理 `/admin/nodes` 使用一张列表和一个「接入节点」入口，按能力展示译文分发与房间文件授权。部署指南和一次性授权均从同一抽屉进入；保留已有凭据的权限边界，不按节点名称合并身份。房间授权已领取不代表实时在线，列表单独展示授权状态。
- 镜像设置、资源索引、自动任务、客户端密钥和节点列表统一使用 `WorkspaceCardHeader`：标题、简短说明、右侧操作。标题与内容固定间隔 12px；说明不单独占据大块区域。
- 清除通用标签的上下外边距，筛选栏、表单、复选框行不再额外增加 40px 空白。其他后台表单、卡片和工具栏同步收紧，保留输入框与按钮 36px 高度。
- 构建从本次 Vite 产物清单汇总共享与页面样式到稳定入口，不依赖会随组件图变化的 CSS 文件名，也不读取上次残留的产物；静态发布包含全部 Vue 样式与脚本。
