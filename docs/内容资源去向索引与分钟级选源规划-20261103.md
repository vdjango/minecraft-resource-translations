# 内容资源去向索引与分钟级选源规划

日期：2026-11-03。状态：已核对本地源站与启动器代码；本文是后续实施方案，本次没有修改运行策略、启用新的缓存或部署服务。现有服务器的配置与在线状态需在实施、部署时另行核对。

## 1. 结论与范围

维护所有实际遇到资源的元数据和下载去向，文件实体按需保存。普通下载、整合包补齐和房间共享共用同一份精确文件索引、来源质量和决策服务。

默认优先使用健康的 CurseForge 等公共直链；Modrinth 为后备，不作为自动模式的第一选择。CurseForge 无相同文件、只有 Modrinth 可用且下载持续慢时，优先准备该文件的加速副本。公共来源恢复后，后续请求重新直下，副本按保留策略释放。

这套优先级用于“自动 / Buggcraft 加速”模式。用户明确手选来源时保留选择，不把手选偷偷改成另一种模式。

“本机缓存”统一理解为后台选定的可用副本：可以是服务器磁盘，也可以是雨云、七牛或其他已配置空间。本地容量为 0 不表示关闭云端缓存。

## 2. 当前已支持与缺口

以下为本地代码事实，不代表所有功能已经在生产启用。

| 能力 | 当前情况 | 需要补齐 |
| --- | --- | --- |
| 房主一次提交文件信息 | 已有批量计划、本地 SQLite 索引核对、按需补传 | 普通下载与房间共用统一响应及选源规则 |
| 地址与文件映射 | 已有 `catalog_files`、`public_lookups`、`public_projects` | 增加统一文件身份、候选可信度及实时质量关联，避免不同入口各选各的 |
| CurseForge 查找 | 已有批量指纹、限量名称搜索、包内元数据提示、SHA-1 与大小校验 | 统一与普通下载的索引入口；未知、失败、禁用下载分别处理 |
| 映射长期维护 | 活跃已识别项目每 20–28 小时读取最近文件元数据 | 保持项目更新与下载健康检查分开，不将每日更新当成分钟级测速 |
| 来源质量 | 通用来源已有错峰采样、30 天样本、速度分档及稳定性判断；默认 6 小时 | CurseForge、Modrinth 的 CDN 与通用来源质量尚未统一，需增加分钟级近期健康状态 |
| 房间来源采样 | 建立映射时采样，默认慢速线 100 KiB/s；连续慢有抑制机制 | 当前独立 `probe()` 未接入维护循环，不能把现有开关当作已运行的定时测速；应合并到统一调度器 |
| 按新质量切换 | 已有映射速度、可用状态参与选择 | 部分入口读取每文件旧速度，没有关联 CDN 的最新健康状态，可能继续选择已变慢地址 |
| Modrinth 优先级 | 房间默认排除直接使用 Modrinth、MCIM；普通下载仍有独立偏好 | 部分启动器配置缺省为 Modrinth，自动模式还可能逐文件测两家；需要统一默认值及旧默认配置迁移，保留显式手选 |
| 缓存未命中 | 普通镜像下载已有立即回退、后台准备缓存的分支 | 对所有入口统一保证不等待下载及上传完整实体 |

主要代码位置：`src/mc_translate/room_sources.py`、`room_cache.py`、`mirror_quality.py`、`mirror.py`；启动器 `core/content_mirrors.py`、`core/downloads.py`、`core/content_routes.py`、`hookup/room_cache.py`。

## 3. 地址表应该记录哪些资源

记录所有实际经过启动器、房间清单、整合包清单，以及已识别活跃项目增量更新的资源。成功匹配也要记录，否则下次仍会重复查询。没有必要抓取两家全站，也不为了建表预下载资源。

将数据分成四类，避免把地址、实体和质量混为一体：

| 数据 | 主要内容 | 生命周期 |
| --- | --- | --- |
| 文件身份 | 哈希、大小、类别、游戏版本、加载器、平台；名称作为显示和搜索提示 | 已验证身份长期保留，冷数据归档 |
| 文件候选地址 | 同一文件的多个提供方、项目/文件 ID、URL、校验依据、地址状态和更新时间 | 随发布状态更新；失效地址停用，保留可追查的原因 |
| 近期健康与长期质量 | CDN、探测位置、延迟、吞吐、成功率、置信度、下次检测 | 近期状态及时更新；明细保留 30 天并汇总 |
| 实体副本与查找队列 | 实体的本地/云端位置、就绪和过期状态；查不到、待查询、重试原因 | 实体依容量与期限清理；队列退避，不无限积压 |

同一文件可同时命中 CurseForge、Modrinth、其他公共来源及多个自有存储。选择结果是随健康状态变化的结果，不将“当前推荐地址”写成不可变绑定。

哈希缺失的 URL 可以登记为未核验候选，不能直接升级为全局精确映射。服务器收到并校验实体后，才把房主提交的 SHA-256 与已验证身份绑定。私人文件只记录必要信息，身份和访问范围不能因去重而变成公开。

没有命中结果也单独记录：真正查无结果默认 24 小时再查，接口超时则短退避重试，不能把超时记成“平台没有”。成功映射长期保留，不随房间临时文件的过期一起删除。

## 4. 正常下载如何选择

统一决策分为：文件身份与访问权限 → 候选是否完全相同 → 地址是否有效 → 当前质量 → 类别策略与可用副本。类别的“仅重定向”始终禁止新建实体。

| 当前条件 | 本次请求 | 后台动作 |
| --- | --- | --- |
| 有健康 CurseForge 或其他快速公共地址 | 返回具体地址，玩家直下 | 登记使用与结果；不新增实体 |
| 某 CurseForge CDN 变慢，另一个已核验公共地址正常 | 改用正常地址 | 保留变慢地址，按计划复测 |
| 公共地址持续低于阈值，已有本地或云端就绪副本 | 使用允许提供下载的副本 | 低频复测公共来源，恢复后再优先直下 |
| CurseForge 无相同文件，Modrinth 有，但已知慢 | 已有副本则使用；无副本则立即返回当前可用后备地址 | 类别允许缓存时排队准备，不能等缓存完成才响应 |
| 所有来源质量未知 | 优先有效 CurseForge，再其他公共地址，最后 Modrinth | 后台采样；不能把“未知”判成慢而缓存整库 |
| 只找到 Modrinth，尚无质量样本 | Modrinth 作为当前兜底，房间已有副本可先提供 | 优先做小样本；确认慢或真实下载失败后缓存，避免一发现 Modrinth 就重复存储 |
| 所有公共地址失败，房主可提供 | 房间已有副本立即复用，否则返回缺失实体清单 | 只授权上传清单中的文件；单个文件就绪即可下载 |
| 无可用来源、无就绪副本、房主也不在线 | 明确显示等待补齐及原因 | 独立重试；不能承诺这种情况也能立即下载 |

“备份并重定向”平时使用健康公共地址，并按策略准备备份；来源故障或持续慢后启用就绪备份。“缓存并提供下载”保留缓存资格，但来源优先规则仍用于节省自有流量。决策结果必须说明这次是否使用公共来源、缓存或故障接管。

缓存、重定向、备份三种模式共用地址索引，不能只有缓存模式才用得到已维护的跨平台映射。整合包 ZIP 与包内模组分别决策，不能把整个整合包都变成房间临时缓存。

## 5. 5 / 10 / 15 分钟检测怎么做

API 查询快不代表文件下载快。分别观察 `api.curseforge.com`、Modrinth API 与实际下载 CDN；选下载地址主要依据对应 CDN 的状态。来源质量以“探测位置 + CDN 主机”为基础，单个文件 404 只影响该文件。

建议默认节奏：

| 对象 | 目标间隔 | 方式 |
| --- | --- | --- |
| 活跃下载正在使用的 CurseForge CDN | 5 分钟 | 轮换最近使用、大小已知的文件，测少量数据 |
| 其他活跃公共后备地址 | 10 分钟 | 按最近需求分批轮换 |
| Modrinth 后备及暂无需求的已知 CDN | 15 分钟，长期无需求逐步退到小时级 | 保持少量探测，不遍历所有模组 |
| 已故障来源 | 短暂冷却后按 5 / 10 / 15 分钟退避 | 探测恢复，不永久封禁 |
| 新版本及特殊映射搜索 | 活跃项目约一天一次，新增清单优先入队 | 拉取元数据；与下载测速分离 |

每个时间加入约 ±20% 随机偏移，错开不同域名；同一个 CDN 同时只探测一个代表文件。后台有全局队列和字节预算，到预算后明确显示“暂停主动采样”，不能仍显示“已确认快速”。5 分钟是高优先级活跃 CDN 的目标，不承诺所有文件每 5 分钟检测一次。

采样先用小 Range，普通上限 128 KiB，疑似慢且预算允许时增到 256 KiB；限制耗时、并发及累计读取，服务器忽略 Range 时也不能整包读完。近期样本不足时显示置信度；非常短的传输只能说明可达或达到某个速度下限，不能伪造高精度测速。

全局主动测速预算建议默认 64 MiB/天，可配置。作为量级参考：一个 CDN 每 5 分钟读 128 KiB，理论净载荷约 36 MiB/天；另一个每 15 分钟约 12 MiB/天，尚未计入重试及协议开销。因此按需求分配预算，不能让每个来源、每个文件都套用最高频率。

速度使用 KiB/s，界面显示“128 KiB/s”，避免与 128 kbit/s 混淆。首字节等待和连接时间单列，数据传输速度另算。近期状态建议：连续 3 次独立有效慢样本、近期均速低于 128 KiB/s，临时降级；连接硬故障可立即对该地址熔断。连续 2 次高于 256 KiB/s 再恢复优先，避免反复跳转。

一次慢样本只降低本次选择信心，有可靠快速副本时可以先选副本；不能因此永久淘汰整个 CurseForge。已在传输的文件不因为后台新样本而强制取消，切源只作用于后续请求或真实失败重试。

长期质量继续保留 7 / 30 天成功率、分位速度、超时率和样本数。速度档位可显示 `<64`、`64–128`、`128–256`、`256–512`、`512–1024`、`1024–2048`、`≥2048 KiB/s`，综合等级为优、良、慢、不稳定、未知；低置信度不得直接获得“稳定优秀”。短期降级不等于长期淘汰。

源站测速只代表源站到该 CDN 的线路，不能当成所有玩家的实际速度。启动器可选择性批量报告实际传输的耗时、字节及错误，不额外逐文件发测速请求；服务端与玩家样本分开展示，玩家样本聚合使用，不能单人报告就改变全网路由。HTTP 307 命中数本身不能证明下载速度或下载完成。

## 6. Modrinth 文件如何补成 CurseForge 映射

1. 启动器扫描文件时一次取得已有哈希、大小、类型、游戏版本、加载器及已缓存的指纹/项目标识；后台线程计算，不能阻塞界面。整个清单一次批量提交，常规计划请求只查本地索引，不等外部搜索。
2. 命中已验证公共来源或现有副本的立即返回。未知且确实需要实体的返回上传清单；只上传这份清单，复用现有受限直传票据和完成核验机制。
3. 后台合并 CurseForge 指纹查询；只需要 Modrinth 元数据时使用批量哈希查询，不因“Modrinth CDN 慢”禁用其文件识别 API。
4. 未命中时，优先从启动器已知元数据和已合法收到的实体里读取名称、mod ID、作者、版本。仅读取 ZIP 中的 `fabric.mod.json`、`quilt.mod.json`、`META-INF/mods.toml`、`META-INF/neoforge.mods.toml`、`mcmod.info` 等有限内容，不把 JAR 整体解压到磁盘或执行。资源包和光影包没有标准模组 ID 时，不生套模组名称查找。
5. 名称、别名和指纹用于找候选；必须比较平台返回的文件哈希及大小。可获得 SHA-256 / SHA-512 时一并核验；已有实体以自身 SHA-256 作为存储去重身份。加载器、平台、文件版本不同的候选不能替换房主文件。
6. 找到完全相同且可公开下载的 CurseForge 文件，记录地址与提供方 ID。这个结果对后续所有清单生效，不再每次重新搜名字；未查到的有限重试，已识别项目按天增量维护。候选地址失效时停用并重新解析，不永久缓存短期签名 URL。
7. 健康公共映射确认后，取消尚未开始的重复缓存；已有实体按安全窗口、正在下载/上传引用、房间租期和普通缓存策略释放。不能切换后立即删除玩家正在使用的对象或已签发的云端链接所指向的对象。

不能假定 Modrinth 的资源都在 CurseForge 存在，也不能认为“同名同版本”等于同一个文件。CurseForge 未提供可用公开下载地址的候选不作为直下命中。

房间临时实体维持默认 8 小时、最长 32 小时；公开映射独立长期维护。关房后停止领取仅该房间需要的新任务，释放上传授权和租期；其他房间或普通缓存仍引用同一对象时继续保留。过期私人临时文件及房间记录按原要求清理。

## 7. 启动器接入与请求数量

沿用现有房间计划和哈希查询协议，逐步让普通内容下载、整合包补齐也调用同一决策层。清单大时有限分块传输，服务端批量 SQL 查询；不对每个文件先 HTTP 查询一次再开始下载。新文件来源识别异步返回增量结果，已就绪项不用等待整个批次完成。

计划结果每项返回：文件身份、当前动作、具体来源、候选后备、原因、质量采样时间、可用副本及是否需要上传。整体返回决策版本、数量汇总和短期有效期；上传只允许计划里明确需要的文件，继续使用已有短期、单文件约束授权，不能把云端长期密钥发给玩家。

自动 / Buggcraft 模式优先读取服务器维护的结果，正常路径不在启动器里对每个文件重新测 CurseForge、Modrinth。原始地址保留为后备：源站接口超时或不可用时直接使用，不因加速服务故障阻断原有下载。实际失败后只补失败文件，最多一次合并反馈，避免频繁重跑整份清单。

多源站通过发布版本化的已验证公共映射与带探测位置的质量摘要协作；每台保留本地查询快照，不能每次请求再同步调用主站。私人房间索引和上传授权不进入公开同步，局部坏线路也不能全网禁用一个 CDN。

## 8. 后台配置与观察

继续使用已规划的菜单，不新增一套散落的配置页：

- **镜像 → 设置 → 下载与来源**：自动来源顺序、慢速线（默认 128 KiB/s）、自动缓存慢/无公共替代文件的开关。分钟级探测节奏、每日预算、恢复线放在同页高级选项；房间不重复填写相同测速参数。
- **镜像 → 设置 → 存储与容量**：缓存实际去向、空间及流量预算。本地、多个云空间独立计量；本页不复制来源质量开关。
- **镜像 → 来源质量**：当前是否参与选源、最近速度及时间、长期分档、成功率、探测位置、下次检查与降级原因。能区分 API 超时、CDN 不可达、文件 404、预算暂停和样本不足。
- **镜像 → 资源列表 / 来源覆盖**：按名称或哈希查文件，展开候选地址、实体位置和“这次为什么选它”。提供“只有 Modrinth”“暂无公共地址”“慢源已缓存”“地址失效”的筛选，不另造一套独立资源管理。
- **镜像 → 房间临时文件**：只显示有效房间资源、上传/缓存数量、字节进度、公共映射节省的上传量；复杂质量配置链接到统一设置。

下载页“使用来源”显示可读结果，例如“CurseForge 直下”“雨云加速 · CurseForge 当前慢”“Modrinth 后备 · 暂无相同文件”，详情再展示原因与样本时间。源站只返回重定向且客户端没有报告完成时，后台统计标为“分配/重定向次数”，不能写成下载成功次数。

## 9. 实施顺序与最小验收

第一步：合并质量采样调度，加入分钟级近期健康，令现有文件映射关联实时 CDN 状态；修正“速度 0 等于已确认快速”等含混语义。保留既有长期评分和预算机制。

第二步：统一房间、普通模组/资源包/光影包与整合包补齐的决策入口，先复用已有索引与受限直传。自动模式调整默认优先级，保留用户显式选择；公共映射不受是否启用实体缓存限制。

第三步：完善活跃资源的后台特殊映射、已识别项目增量维护、质量图表和具体决策原因。后续再加入可选玩家样本与多源站公共摘要同步。

发布前只做必要场景：批量清单同时命中公共地址/缓存/未知；CurseForge 变慢与恢复；Modrinth 唯一匹配；不同加载器同名文件拒绝替换；缓存未命中立即回退；房主关房与授权失效；本地 0 但云端可用；源站不可用不阻断公共下载。使用小文件和受控假时钟验证调度、预算，不批量下载模组整站。

## 10. 本次落地与清理约定

本次已实现统一内容选路与后台分钟级采样：活跃 CurseForge 默认 5 分钟、备用 10 分钟、Modrinth 15 分钟，随机错峰；同一 CDN 只抽取已登记的代表文件，内容样本最多 128 KiB。全局共用每日预算，默认 64 MiB，避免房间查找与质量模块重复测速。小于 64 KiB 的成功传输不作为短期速度判断依据；连接错误仍记录，文件 404 不当作整个 CDN 故障。

短期状态与长期评分分开。连续三次低于默认 128 KiB/s 才判持续慢，恢复需要连续两次达到阈值的两倍；过期数据退回未知。速度 0 表示没有测速证据，不能据此取消云端备份或删除房间实体。房间请求不现场测速、不等公开 API 或云端上传完成。

房间清单和公开哈希查询复用同一选源层。公开查询按 300 项一批访问本地索引；一次最多 3000 个哈希。一次请求共用配置与 CDN 质量快照，避免对每个文件反复准备相同信息。公共映射可在关闭房间实体缓存时继续查询。

启动器自动模式和 Buggcraft 优先模式先批量查询哈希计划；整合包中的重复文件共用查询结果。源站无记录、超时或不可达时保留发布方地址后备，不等待缓存完成。已取消逐文件的额外测速，保留用户明确配置的平台和自定义优先级；旧设置中的“自动测速”值兼容保留，含义改为采用源站共享观测。

后台入口沿用现有导航：

- **下载与来源设置**：统一慢速阈值、预算及高级周期，房间设置不再重复提供一组测速参数。
- **来源质量**：内容 CDN 当前健康、最近速度、下次采样、长期评分、仓库表现和采样曲线。
- **来源覆盖**：新增公开映射列表，支持文件名、完整哈希、平台、目录状态及“仅有 Modrinth 地址”筛选；不显示私人房间路径或未命中搜索提示。

按本次确认，房间不作永久私人文件仓库：

| 数据 | 期限及处理 |
| --- | --- |
| 已核验公开文件地址、哈希和大小 | 独立保存在公共目录，可跨房间复用；不因房间过期删除 |
| 房间上传的实体（含没有公开发布的模组） | 继续按临时期限和配额管理，默认 8 小时、最多 32 小时；关房释放该房间需求 |
| 私人房间路径、未命中查询及房间搜索状态 | 最后一个房间引用清理后删除；公开地址保存在公共目录，不依赖保留这些房间记录 |
| 正在读取、上传或仍有其他房间引用的实体 | 安全退出或最后一个有效需求结束后再清理；已发出的短期直传授权到期后处理遗留对象 |

清理不把私人实体提升为普通镜像永久缓存。本地与云端容量仍独立约束，云端临时实体沿用已有过期删除流程；这里只更新规则，没有对生产服务器执行一次性批量删除。

可选的玩家真实吞吐反馈、多源站公共摘要同步仍属后续增强，不将本节点测速冒充玩家实际下载速度。本次为本地实现，尚未部署网站或发布新的启动器安装包。
