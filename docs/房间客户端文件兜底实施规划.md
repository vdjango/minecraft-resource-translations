# 房间客户端文件兜底实施规划

更新：2026-11-01。此文档是启动器、联机节点、资源源站三个项目的共同实施与验收清单。

## 一、目标与边界

房间自动同步客户端时，单个模组下载失败不能中断其余文件；成功文件保留并校验，后续只补齐缺失部分。必需文件没有全部校验通过，不能把配置标为完成或启动游戏。资源包、光影等可选文件可以明确提示后跳过。客户端本质是模组、游戏核心、加载器、库文件、资源等文件的组合，源站继续为这些普通资源提供正常的镜像与重定向，不存储整包副本。

整合包导入与下载复用现有缺失文件队列、六次自动重试、续传和手动补齐流程，修补与房间准备不一致的部分。普通外部整合包没有在线文件提供者时，不能声称源站可以凭文件信息生成不存在的实体；仍需公开来源、用户补齐或作者提供文件。

先提交文件信息，不先上传文件或整个整合包。源站优先让客户端直下公开来源；仅对确实无法获取或持续过慢的关键文件请求房主补传。房主只发送源站返回的实体清单。

本次不改变游戏数据传输、P2P/中继选择、账号体系以及普通 Minecraft/Java/加载器镜像缓存的生命周期。当前要求是启用启动器内的自有源选项、完成源码与本地可控链路测试，**暂不构建、发版或更新下载站**。待公开域名可用、端到端验收通过，再另行决定部署与发版。

用户概念统一为“临时下载加速”：启动器在后台确认模组、运行库等文件能否正常获取，只有缺失或持续过慢的文件由源站临时缓存，帮助玩家度过来源不稳定的时段。房主无需执行“上传客户端”、管理实体或关注清理时刻。共享提示可说明通常保留 8 小时，不显示精确到期、倒计时或清理通知。服务器到期回收只是内部选源事件，下载中断点保留，自动走正常来源、P2P 或按新需求重新申请缓存，不因到期本身弹窗报错。

## 二、分工与身份认证

| 项目 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 联机节点 | 利用现有已认证房间会话校验成员身份、踢出状态、文件提供者和共享开关；签发 5 分钟授权 | 大文件存储与转发 |
| 资源源站 | 上传时验证节点签名；接收信息清单；返回重定向/缓存/待补齐计划；按需接收、校验、公开分发、清理实体 | 新建账号密码登录体系；下载者身份认证 |
| 启动器 | 房主提供文件信息并按清单补传；成员下载、续传、校验；展示缺失文件和原因 | 决定服务器必须缓存什么；匿名任意上传 |

节点与源站使用服务端密钥签发和验证 HMAC-SHA256 短期授权。源站后台生成 10 分钟有效的一次性接入邀请，节点后台粘贴后通过 HTTPS 领取独立发行者与密钥并立即保存生效；管理员可在源站撤销节点。保留环境变量配置作为旧部署兼容路径。密钥绝不下发给启动器，也不写入仓库；撤销某个节点不会影响其他节点。

授权绑定发行者、房间 ID、配置 ID、模组/资源清单哈希和数量、上传角色、签发与到期时间。源站以发行者 + 房间 + 配置区分实体上传请求与缓存需求；全局按 SHA-256 去重存储实体。房主才能提交完整信息清单和上传。下载和按哈希查询计划不验证玩家身份，未公开模组补传后也能被他人获取，不实现房间私有读取。权限变化后旧上传授权最多存活 5 分钟，不能承诺即时撤销。

文件共享关闭时，节点停止签发新上传授权；已经发布的文件不会变回私密。旧节点或未配置密钥时保留本地/P2P 下载；绝不降级为匿名源站上传。启动器开关名为“允许文件共享与临时下载加速”，旁边提示：“优先正常下载，仅为缺失或持续过慢的模组等文件提供临时缓存，通常保留 8 小时。共享文件可被他人获取；如含敏感或不希望公开的内容，请勿开启。”

## 三、完整流程

1. 房主开启房间文件共享，启动器从节点取得写授权。
2. 房主在后台读取当前实例的模组与可选资源，计算 SHA-256、SHA-1、大小和相对路径；复用已记录的公开来源，并用 CurseForge 指纹批量查询相同文件。只传信息，不逐个下载测速。
3. 源站验证清单与节点签名中的数量、清单哈希一致，再保存信息。
4. 源站返回每个 SHA-256 的计划：`redirect` 公开来源直下，`cached` 临时实体已就绪，`upload` 请求房主补传，`pending` 等待信息或容量恢复。只有房主响应中含有上传清单。
5. 房主最多同时补传两个被请求文件。源站限制大小、容量、并发和磁盘余量；校验大小、SHA-256、可选 SHA-1 后原子发布。中断文件绝不作为成功实体对外提供。
6. 成员先复用本地已校验内容，再按公开计划下载；普通游戏资源沿用现有源站路径。文件兜底不要求建立 P2P，也不要求下载者持有令牌。
7. 失败文件进入队列，不取消其他独立下载。公开源自身的自动重试预算耗尽后，不在每轮等待时重复轰炸同一地址；成员集中报告缺失，等待房主补传并刷新计划，最多六轮自动补齐。
8. 自动补齐后仍缺必需文件，展示名称、原因和继续方式；已完成的 SHA-256 缓存及有效断点保留。重试只处理缺失内容。
9. 全部必需内容和加载器校验通过，并确认房间配置未改变，才能原子发布可用实例。

## 四、缓存决策与空间控制

启动器访问 Buggcraft 自有源时使用“仅源站提供内容”请求标记。普通用户访问仍按后台镜像策略处理；携带该标记的模组及游戏资源只允许源站提供经过源站获取的文件，或者明确返回不可用，绝不重定向回 Modrinth、MCIM 等其他第三方地址。这样源站失败后，启动器才能进入房主文件或等待补齐流程。

| 情况 | 决策 |
| --- | --- |
| 公开来源可用；速度未知或样本不足 | 直接下载，不先缓存或等待测速 |
| 公开来源无相同哈希文件，包括未公开模组 | 请求房主补传该文件 |
| 成员已实际下载失败 | 只为报告的缺失文件申请实体兜底 |
| 连续至少两次后台采样低于阈值，且观测未过期 | 后续计划允许请求补传；默认阈值 100 KiB/s |
| 后续采样恢复快速稳定 | 后续未缓存文件优先直下；已有实体正常到期，不中断现有下载 |
| 超过单文件/总容量/磁盘余量/流量限制 | 返回明确等待原因，保留已有下载与其他类型缓存 |

后台每分钟检查一次工作队列；同一来源默认每 6 小时采样一次，每次最多 128 KiB，默认每日总预算 32 MiB。限制超时和跳转次数，每一跳均检查允许的公开域名并禁止私有地址解析。请求下载计划时不等待测速。

观察的是源站到来源的速度，不能据此声称所有用户网络都慢。已验证的实际失败优先用于该文件的补齐；单个路径不存在不应直接判定同一 CDN 的所有文件都失败。

下载选择遵守“启动器选什么就是什么”：自动模式只尝试默认选择的可用提供方（内容文件为 CurseForge，游戏文件为 BMCLAPI），手动选择 CurseForge、Modrinth、MCIM、官方或 Buggcraft 时只访问该选项的地址。**唯一自动备用地址是 Buggcraft 自有源站**，不能自动换到另一家第三方源；房间已授权的房主文件传输是独立的内容兜底。若所选源的文件地址不可映射，不偷偷回退官方地址；给出明确失败信息。Modrinth 与 MCIM 不自动加入候选或参与自动采样；只有明确选中 Modrinth 才按文件哈希查询其地址。手动选项需明确提示：Modrinth 速度极慢，不建议轻易尝试；MCIM 不推荐。CurseForge 的 `mediafilez.forgecdn.net` 保持原地址，不替换成 MCIM 域名。更改选项后，进行中的整合包任务取消旧连接并使用原断点从新选项继续；房间补齐下一轮读取最新选项。

客户端临时缓存需求默认保留 8 小时，后台可调 1–32 小时。每个房间独立计时，同一 SHA-256 实体只保存一份，实际清理时间为所有有效需求的最晚到期时间。同一房间的访问、轮询计划或重复提交信息不会续期。旧需求到期后，只有新的实际缺失需求才可再次申请，不由后台轮询自动永久续期。清理跳过正在提供下载和补传的文件；读完之后后续清理再释放空间。

交集验收例：A 房间第 0 小时申请模组，需求到第 8 小时；B 房间第 5 小时申请相同模组，需求到第 13 小时。期间只存一份实体，第 8 小时不删除，第 13 小时所有需求到期且没有读取或补传时才清理。32 小时上限约束每次有效需求，跨房间复用不会再存一份相同文件。

该上限**仅用于房间客户端文件实体**，包括模组、资源包、光影。Forge 安装器、Minecraft 核心、libraries、assets、Java 等沿用现有分类策略、来源质量评估和容量管理，不受 32 小时上限影响。

自动内容搜索仅查询 CurseForge；明确切换到 Modrinth 后才访问 Modrinth 元数据或按哈希寻找同一文件。

## 五、后台页面

资源源站管理增加“临时加速”页签，复用现有后台登录；同页生成一次性节点接入邀请并查看或撤销已接入节点。节点后台“资源源站”卡片粘贴邀请即可接入或断开，无需复制密钥、SSH 或重启。

- 启用开关、节点密钥配置就绪状态。
- 客户端实体保留时长，明确默认 8、最多 32 小时。
- 独立临时容量、单文件上限、慢速阈值。
- 后台采样开关、间隔、每日流量预算。
- 当前实体数量、占用、补传数量、读取数量。
- 最近文件决策及原因，来源采样速度、连续慢速次数和采样时间。
- 明确说明：先传信息，按需补传；不上传整个整合包；其他资源分类策略不受本页保留时长影响。

源站 `/room-cache/` 必须路由到独立资源进程，上传时保留 Authorization；临时响应使用 no-store，避免 CDN 在源站需求到期后继续持有临时文件，关闭代理临时文件和请求缓冲。公开镜像路径现有缓存策略继续使用。no-store 不代表文件私密，任何取得哈希地址的人都可下载。

## 六、接口约定

| 接口 | 调用方 | 权限与内容 |
| --- | --- | --- |
| 节点 `room.request: content_cache_grant` | 已认证房主/成员 | 成员取得公开源站地址；文件提供者可设置共享并领取上传令牌 |
| 源站 `POST /room-cache/plan` | 房主 | 提交完整 files 信息；验证节点签名与配置；返回逐文件计划和请求补传清单 |
| 源站 `POST /room-cache/resolve` | 公开 | 查询 wanted 哈希、报告已有清单中的 failed 哈希；不能登记路径、来源或上传实体 |
| 源站 `PUT /room-cache/files/{sha256}` | 房主 | 仅接收已由计划请求且属于当前房间的实体 |
| 源站 `GET/HEAD /room-cache/files/{sha256}` | 公开 | 已缓存实体支持 Range；否则重定向可用公开来源或返回等待原因；不检查下载者身份 |
| 源站后台 `POST /v1/admin/room-cache/nodes` | 源站管理员 | 生成一次性接入邀请或撤销节点；列表不返回密钥 |
| 源站 `POST /room-cache/nodes/claim` | 持有邀请的节点 | 一次性领取该节点的发行者与密钥，过期、重放或撤销均拒绝 |
| 节点后台 `POST /api/admin/room-cache` | 节点管理员 | 粘贴邀请接入或断开，保存后立即影响新授权 |

上传授权放入请求头，不放 URL、日志或整合包；公开读取不发送授权。源站重定向后，启动器访问外部 CDN 时不携带授权。房主补传路径限于实例内 `mods/`、`resourcepacks/`、`shaderpacks/` 的单层文件，拒绝绝对路径和越界路径；游戏核心、库、资源、加载器复用既有镜像路径与策略。

## 九、部署与运维

本轮仍在独立开发分支：Buggcraft 源已在启动器源码启用，但用户反馈公开域名尚未开放。下面的生产记录属于先前部署版本；本轮的源选择、节点 Web 接入和等待补齐界面均未发布或部署，不应据此宣称玩家已能使用完整新流程。

官方公开入口为 `https://mirror.bugg.icu`，后台入口为 `/admin/mirror#room-cache`。上传、计划与公开文件路径 `/room-cache/` 均转发至独立资源进程；配置模板默认端口为 18449，当前生产环境沿用既有服务配置的 **18450**，普通页面和后台仍由 18448 提供。使用 `deploy/nginx-mirror.conf` 或 `deploy/cloudflared-mirror.yml` 时须适配实际服务端口，不将临时文件路径套用全站强制缓存规则。

新节点优先使用后台的一次性邀请自动接入，保存后即时生效；已有部署继续支持 `TRANSLATION_ROOM_CACHE_KEYS` 与节点侧 `BUGGCRAFT_ROOM_CACHE_URL`、`BUGGCRAFT_ROOM_CACHE_ISSUER`、`BUGGCRAFT_ROOM_CACHE_SECRET`。旧环境变量模式变更后需重启 Python 服务。密钥仅存于服务器受限配置或数据库，不进入仓库、客户端或 URL。
